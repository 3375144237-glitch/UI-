# Figma 与 App 界面验收

适用于用户提供设计稿和设备截图、要求检查静态界面还原的任务。命令参数见项目 [`README.md`](../../../README.md)；文案分类须另读 [`COPY-CLASSIFICATION.md`](COPY-CLASSIFICATION.md)。

## 开始前

1. 创建项目、文件或验收目录前，完整阅读 workspace 根目录的《问题与报错日志.md》；可复用的新问题、原因和解决办法记入中心日志，不自动复制到在线验收表。
2. 收集 Figma 链接或设计图、设备截图、设备名称和 REM/PX 实现方式。PX 需用户确认设备自身 @2x 目标宽度，以及截图已为 @2x 或其倍率；不能按机型、物理分辨率或文件名推断。共用信息按批次收集一次，页面/状态由 Codex 逐图配对。
3. 对照前运行 `~/.codex/bin/figma-comments "<Figma链接>" --json`，读取评论正文、回复和锚点，按节点/区域绑定 PX/REM 与例外说明。带 `node-id` 的链接只覆盖该节点及子节点；读取失败须标明未读范围，不发布受影响范围的最终结论。
4. 检查并复用已有“<项目名>验收”页；用户指定其他页时沿用。原设计页不改。图片分批导入，每批完成对位、问题登记和证据归档后核对图层与画布落位。未同步时只报告本机状态，不声称共享端可见，也不主动同步。
5. 保留原图不覆盖。每轮使用新目录 `outputs/design-review/<日期>/<页面-设备>/`，存输入副本、归一图、证据、`review.json` 和表格。截图与报告不随代码提交，除非用户明确要求。

## 配对与缩放

- 多页面截图逐张编号，按画板、标题、文案、图标、顺序及布局锚点匹配页面、状态和版本；长设计稿还记录设计起点/区段。`配对与进度.md` 逐图留原路径、设计区段、配对依据、把握度、输出目录及覆盖状态（已验收/未验收/未处理）。相似候选、状态不明或截图外内容不得推断；信息不足标未验收并说明原因。无问题页面也保留并排图。
- 本项目 720px 宽画板即 @2x 基准，手动导出选 1×并核宽；可用 Figma 连接读取设计图时先核实际尺寸。整页或某一区域明确标注 REM 时，先将整张设备截图副本等比缩到设计稿宽度，再用该图验收标注范围内的元素；不能只缩放单个元素。PX 按用户确认的 @2x 宽度及截图倍率处理；截图已为 @2x 时用 `--already-2x`。资料缺失或冲突只暂停受影响批次；不拉伸图片来消除差异。宽度不同按 Figma 约束推导预期，依据不足记未验收。
- 多张截图对应长稿时，以独特锚点配连续区段，`--design-y` 填设计稿 @2x 纵坐标；必要时用相邻截图确认滚动连续性，不拼接不连续区域。顶部局部文字先核滚动偏移和裁切边界，不能直接判缺陷。
- 每组配对单独执行 `compare`；它不会自动识别整批图片。输入原文件名保留并另编序号。缩放、页面/状态或版本依据不足时，记录受影响范围和缺失输入。

## 逐元素验收

1. 以设计稿为基准，列出验收范围内每个应显示的元素，重复组件逐实例列出；隐藏/辅助图层及评论明确排除区域不计。逐项在同状态设备截图中查找、对位，检查样式、位置和大小，不能用模块整体正常代替。
2. 在 `review.json` 为每项记录 Figma 节点 ID、设计 bbox、对应设备原图 bbox、样式/位置/大小的实测与结论。应出现却找不到的元素，核实状态和视口后登记缺项；遮挡、视口外或约束不足的元素标未验收并写原因，不标通过。完成前核对设计清单与结果一一对应。
3. 先记录原始 bbox 和间距，再移动设备裁片副本对齐同一文字、图标、边缘或中心锚点。REM 元素在等宽基准下应能与设计稿对应元素的边界和轮廓完全重合；不重合时只平移裁片检查：平移后可重合，结合原始 bbox 和相邻元素间距判断位置/间距问题；仍无法重合，则测量元素自身的宽高、形状或内部布局差异，分别记录原因。整屏红色 50% 叠图只作初定位；裁片不缩放或重排内部元素。父容器位置与子元素到四边、相邻元素间距分别核算，差值为设备减设计的归一后 @2x px；移动后坐标不能替代原图坐标。像素图无布局框时只记可见边界并标估算。
4. 弹窗独立裁出并按弹窗顶部对齐，再验四边和内部元素；不能用屏幕顶部作锚点。图片容器、图片可见边界、icon 节点框与可见轮廓分别检查尺寸、位置、裁切和遮挡。
5. 深色“测试 ▶”、红色“调试”和蓝色“LiveHybrid”悬浮标记不参与验收。遮挡内容先找同设备、同页面、同状态的无遮挡补图并记录来源；找不到则仅将该区域标未验收。叠图文字重影须回查同状态原图和 Figma 节点，不把叠合假影报成问题。
6. 文字节点先按文案分类规范逐项记录 F/D/T/U、依据和把握度，四类都验样式。可编辑文字用 `getStyledTextSegments(['fontName','fontSize','lineHeight','letterSpacing'])` 读取属性；图片/转曲文字不能猜字体、字号或 dp/pt。用户确认 U 类后更新项目 `copy-registry.json`，补查新确认的固定文案。

检查顺序为功能/缺项、模块外观与状态、内容、图片/icon、文字、适配、间距。每张卡片及子元素分别测父/子 bbox、四边和相邻间距，`spacing_checks` 留设计值、设备值、差值、状态与把握度；未量完的页面只能记部分验收。P0：功能/模块/内容缺失，明显的尺寸、布局、样式或圆角错误，内部元素、图片容器或 icon 尺寸不符，固定文案或文字样式不符，设备适配问题，以及超过 4px 且明显破坏布局的间距差；卡片底色缺失属 P0。P1：4px 以内且影响较低的间距差。不同属性的独立差异分别编号。

## 证据与交付

- 同一页面的问题共享稳定页面组号，各问题使用独立 ID，记录类别、设备原图 bbox、设计依据、预期、实测、差值、建议和同源局部证据。证据须含设计区域、带编号的设备原图裁片及移到设计锚点的红色 50% 对位图；整屏叠图或无来源裁片不足以定案。红框只画设备图且只圈本行问题，框线须完整落在裁片内。设计稿侧标题为“设计稿”。Figma 验收页留设计、设备与对位图，不写问题描述。
- 证据图设备侧 1-2 个红框时写明对象、属性和正确设计值；纯文案问题写“XX区域文案内容与设计稿不一致”，不复述原文；缺项写明应有元素。超过 2 框简要归纳，细值留 JSON；超过 2 框的间距问题在备注放 Figma 研发模式设计值截图。不猜设计值，也不写笼统的“样式不对”。
- 验收表固定六列：设备、截图、问题描述、优先级、验收状态、备注；设备分类使用 `IOS`、`安卓`、`鸿蒙`、`PAD`、`PC`。问题行状态统一“待修复”，未经用户授权不改为其他状态。每行独立图文对应；导出前核对表头、红框、描述、ID、bbox 和证据链接。无问题、未验收及未覆盖范围单列在进度汇总，不伪装成问题行。
- 同一差异跨设备用 `shared_issue_id` 合并为一个问题，但每台设备仍保留独立来源、bbox、测量和证据；不按文字相似自动合并。本地 Excel/Markdown 是归档快照，`review.json` 保留逐设备实例。使用当前电子表格 Skill 创建正式可编辑 `.xlsx`；辅助证据标题和备注脚本见 README。
- 当轮钉钉链接由用户提供，以该表为协作主表；无链接先询问目标，仅访问用户指定文档。人工改写的数据按稳定问题 ID 和字段持续保护，只有用户明确解除才恢复自动更新；人工清空、改回旧值或排序不解除保护。无可靠编辑历史、写入基线或并发校验时跳过已有单元格；仅调整版式不触发保护。插图前后核对目标单元格、画布和保存结果，刷新回读；不以旧 Excel 覆盖在线人工修改。

最终核对每张输入图只有一个覆盖状态；设计元素清单逐项有结果；问题表与 JSON 的唯一问题数、设备实例和证据一致。没有可靠的 Figma 属性、响应式约束或设备截图时，只报告已证实范围；静态截图不能证明动画、运行性能或截图外状态。
