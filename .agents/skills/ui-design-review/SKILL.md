# Figma 与 App 界面验收

当用户提供设计稿和 App 截图，并要求检查界面还原情况时，使用本 Skill。

## 开始前

1. 创建文件或新的验收目录前，完整阅读 workspace 中的《问题与报错日志.md》。
2. 按批次收集 Figma 链接或设计稿、截图文件夹、设备名称和 REM/PX 实现方式。PX 另需设备自身 @2x 目标宽度，以及截图已为 @2x 的声明或截图倍率；REM 按宽 720px 等比处理。共用信息只收集一次；页面名称、可见状态和设计稿配对由 Codex 逐张识别、记录，不要求用户逐页填写。不得按机型名称或物理分辨率猜倍率。
3. 推荐把待比较的设计稿放在 `screenshots/design/`，把人工手机截图放在 `screenshots/device/`。也可以直接使用聊天附件的本机路径；路径传给命令后，程序会将原图副本收进验收目录。两个输入目录中的图片和 `outputs/` 报告默认被 Git 忽略，不会随代码提交。
4. 保留用户提供的原图，不覆盖、不修改。每轮验收使用新目录：`outputs/design-review/<日期>/<页面-设备>/`。原图副本放在该目录的 `inputs/`，归一后的比较图、差异预览、局部证据图、`review.json` 和 Excel 报告也放在该轮目录中。
5. 某批次必需的缩放信息缺失或冲突时，暂停该批次缩放，并写明缺少的输入和受影响范围；其他信息完整的批次可继续。页面覆盖记录用“已验收、未验收、未处理”区分处理进度；问题表中的验收状态统一写“待修复”，不把覆盖进度当作验收结论。
6. 先检查 Figma 文件的页面列表：同一链接已有对应“<项目名>验收”页时直接复用，不新建重复页；没有时才新建，用户另给验收文件/页时沿用其地址和名称。原设计页不改。把设计稿和设备图分批放入验收页；逐模块/元素移动到对应设计位置，尽量无缝重合。每批完成对位、问题登记和证据归档后再导下一批；检查图层与画布确认内容已落位，不得停在图片导入/放置状态。若 Figma 提示未同步，记录本地状态且不宣称共享链接可见，不主动触发同步或重连。

一个设备截图文件夹按用户说明视为同一设备；该文件夹内文件名可以没有页面含义。保留原文件名，用序号辅助整理，不按文件名或分辨率推断页面或缩放倍率。用户提供该文件夹对应的设备和缩放信息即可。

## 多页面批量验收

- 用户可提供一个包含多页面截图的文件夹，不必重命名或列出各页面/状态。Codex 先清点图片，保留原文件名并为每张分配唯一编号；再结合 Figma 画板、标题、文案和布局识别页面及截图可见状态。不要从静态截图推断截图外的登录、权限或业务状态；证据不足的截图记录为“未验收”，并简述缺失的依据。
- 在本批次输出目录维护 `配对与进度.md`，逐张记录编号、原文件相对路径、页面/可见状态、Figma 画板链接或设计图片、长稿区段、匹配依据、把握程度、处理状态和结果目录。名称是工作标签，Figma 节点或设计图片路径用于追溯；不因名称相同就合并不同画板。
- 配对表中的每张截图必须能追溯到具体设计画板/区段和原始截图；无对应设计稿、状态无法判断或配对不唯一时记录为“未验收”，说明缺失依据，不把它记作已验收。
- 每个不同的 Figma 页面分配一个稳定页面组编号，如 `P08`。同一张长设计稿被多张设备截图覆盖时，所有对应区段共用该页面组编号；该页问题按 `P08-01`、`P08-02` 连续编号。相同页面的不同截图可以各自保留验收目录，但须在 `页面问题汇总.md` 按页面集中索引。跨页面共享组件问题单独编号（如 `NAV-01`），列出受影响页面。
- 唯一明确的配对直接验收；相似页面、重复模块、多个设计版本或缺少对应设计时记录为“未验收”，列出截图编号和缺少的依据。先继续其余已明确配对的截图。
- 多图可分组处理，每组完成就更新进度。收尾核对每张输入图均有“已验收”“未验收”或“未处理及原因”的记录，并汇总数量；没有问题的已验收截图也要记录。没有截图的页面/状态不能算已验收。
- 页面识别与配对由 Codex 执行；现有 `compare` 命令每次只处理一组配对，不会独立识别整个文件夹。`--page` 由 Codex 按证据填写；用户手动运行时也可省略该可选参数。

## 多张截图对应长设计稿

- 先逐张查看设备截图，再在长设计稿中寻找对应纵向区段。依据独特标题/文案、图标、图片、组件顺序和布局锚点定位；滚动位置本身不作为匹配依据。
- 整理配对清单：设备截图原文件名、对应设计稿起始纵坐标与区段、页面/状态、匹配依据、把握程度。明显唯一的匹配可继续处理；重复模块、相似页面或找不到足够锚点时记为“未验收”，列出候选区段和缺失依据，不强行配对。
- 按每张截图处理一组配对。长稿区段的纵坐标使用设计稿 @2x 像素坐标；运行 `compare` 时传入 `--design-y <起始纵坐标>`，工具从该位置裁取与归一后设备截图等高的设计稿区段。该区段坐标会记录在验收信息中。每张截图使用独立输出目录。
- 若某张截图在长稿中跨越相邻区段，可按其实际连续范围选择起点；不要把不连续的设计区域拼接后伪装成整页。可用前后相邻截图验证滚动连续性和重复内容的位置。
- 仅当裁出的设计稿区段与设备截图归一后尺寸相同才运行像素差异定位。PX 设备宽度不同于720px时，不拉伸720px设计稿；根据 Figma 自适应规则判断，规则不足时记录为未验收并说明缺少的规则依据。

## 处理截图

设计稿画板本身宽 720px，这已是本项目 @2x 验收基准；手动导出选 1×，确认图片宽 720px，不再选 2×。也可先提供 Figma 链接，由 Codex 经可用连接读取画板并核对参考图实际尺寸；无法读取或无法取得合适参考图时，再请用户补充导出图。

- REM：运行命令时使用 `--mode rem`。程序会把设备截图副本等比缩放至宽 720px，高度随比例变化。
- PX：使用 `--mode px`，并填写用户确认的设备自身 @2x 宽度 `--target-width`。如果截图已经是该设备的 @2x 图，增加 `--already-2x`；否则填写用户确认的截图倍率 `--screenshot-scale`。程序会检查倍率推算结果是否与目标宽度吻合。
- 不得拉伸设备图或修改原图。全屏红色 50% 叠图只是初始定位参考，不能当作验收结果。将设备图副本裁成单个模块/元素后，把对应裁片移到设计稿的对应模块；按相同文字、图标、边缘或中心锚点调位置，尽可能让轮廓与字形无缝重叠。裁片只移动、不缩放、不重排内部元素；无法重合后再判断尺寸、周围间距或位置差异。PX 按用户提供的换算尺寸处理；REM 先把整张设备截图等比例缩到设计稿宽度，再裁模块。所有位移和测量都记录为处理后设备截图 @2x 像素。
- 验收弹窗时先从设备截图中独立裁出弹窗，只比较弹窗与设计稿弹窗。将两张弹窗裁图的顶部边缘对齐，不使用状态栏、屏幕顶部或整屏位置作锚点；弹窗内部仍要逐模块/逐元素移动对位。
- 生成每条问题的局部证据板：包括设计稿对应区域、带问题编号的设备原图裁片，以及已移动到设计锚点上的红色 50% 叠图。问题截图必须来自同一设备原图，并将其原图 bbox、设计区域、裁片目标位置写进 `review.json`。整屏叠图、单张红图或没有设计参照的设备裁片不能代替问题证据。

REM 命令示例：

```bash
.venv/bin/python scripts/ui_review.py compare --design screenshots/design/page.png --device screenshots/device/page.png --mode rem --device-name "设备名称" --page "首页/默认态" --out outputs/design-review/YYYY-MM-DD/首页-设备
```

PX 命令还需增加 `--target-width <设备自身@2x宽度>`，并根据截图情况选择 `--already-2x` 或 `--screenshot-scale <用户确认的截图倍率>`。

程序会保留输入原图，并生成处理后的图片、三种锚点叠图、`review.json`、差异预览图和 `report.xlsx`。`align` 可调整当前叠图并更新复核记录：

```bash
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment left --offset-y 0
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment right --offset-y 12
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment center --offset-y 0
```

纵向偏移用归一后设备图 @2x 像素，正数下移。整屏锚点只用于初定位；最终必须在 Figma 里逐模块、逐元素对位，弹窗只按弹窗顶部锚点。

## 验收执行顺序

严格按以下顺序完成；缩放资料不全时暂停该截图，Figma 配对、状态或版本依据不足时记录为未验收，并简述缺失依据。

1. **检查缩放**：先记录设备原图宽高、用户确认的 REM/PX 方式、目标设备 @2x 宽度和截图倍率，计算是否要缩放并记录处理后尺寸与比例。原生 @2x 不缩放；REM 等比缩至宽720px；PX 按确认的目标 @2x 宽度换算。不得按机型或像素猜倍率，不拉伸图片。
2. **在 Figma 比对**：确认目标画板、状态和版本，复用已有验收页；先读节点边界、自动布局与约束，再用同倍率设备裁片逐元素对位。弹窗量四边及内部间距。对可编辑文字用 `getStyledTextSegments(['fontName','fontSize','lineHeight','letterSpacing'])` 读取属性并将值、节点 ID 记入 JSON；只报设备表现支持的差异，不猜。状态、版本或响应式依据不足时标未验收，宽度不同则按约束推导预期。
3. **截图并记录**：Figma 验收页保留设计稿、设备截图与对位图，不写问题描述。沿用六列和原表格式，截图列放并排对比图；问题描述和备注按下述红框数量规则处理。完整测量、原图 bbox、证据和 ID 记入 `review.json`，不增加表格列。

## 人工检查与记录

### 检查顺序与卡片间距

每页依次检查功能/状态、模块外观、模块内容、图片与 icon、文字、适配和间距。重复卡片按实例逐个检查；多个独立差异分别编号，不把位置、尺寸和间距合并成一条笼统问题。动态数字不比较具体值，但核对字段、占位、字体和对齐。

卡片内部间距是必查项，不能用卡片整体位置或差异图代替。先固定卡片父容器锚点，记录 Figma 节点 ID、边界和尺寸；再逐个识别子元素，并在原始截图坐标中记录其 bbox。分别计算元素距卡片内沿的左、上、右、下间距，以及同一行/列相邻元素边界之间的横向/纵向间距。公式统一为：左=x元素−x卡片；上=y元素−y卡片；右/下=卡片右/下边界−元素右/下边界；元素间距=后一个元素起点−前一个元素终点。使用 Figma 节点/自动布局值作为设计值，同倍率设备截图中的 bbox 作为实测值，记录差值（设备减设计），单位为 @2x px。超出卡片时记录负间距，并写“超出卡片左侧8px”等方向和数值。

先记录原始位置和间距，再做视觉对位。移动设备裁片只用于叠图的副本；不得用移动后的坐标计算原始间距，也不得移动卡片父容器来掩盖子元素差异。设计和设备宽度不同，按 Figma 约束换算预期，不缩放截图来消除差异。

在 `review.json` 为每张卡、每个子元素记录 `spacing_checks`：容器/元素名称、Figma 节点或来源、设计 bbox、设备 bbox、设计与实测四边间距、差值、状态（通过/问题/未验收）及测量把握度。每个可见卡片及子元素都要有记录；没量完或无法配对时页面只能是部分验收。只有像素图而无法确定元素布局框时，记录可见边界并标“估算”；不得把估算写成精确布局值。Figma 版本依据不足时，依赖该版本的测量记录为未验收并说明原因；状态专属或无法配对的元素不作推断，共享元素仍按设计稿状态测距。

统计每项证据图 iOS 侧的红框数，不计设计稿侧。1-2 个框时写清对象、属性及正确设计值，格式如“XX颜色/字号/尺寸与设计稿不一致。设计稿为：XX”；例如紫色背景圆角设计值24px、数据卡片背景色#F8F5FF。值须来自 Figma 属性或研发模式。纯文案内容不同写“XX区域文案内容与设计稿不一致”，不复述两边文本；缺项指出应有项。超过2个框时沿用简短归纳，多处只列名称并写“不对，需要与设计稿保持一致”，不罗列测量值。禁止笼统写“样式不对”“显示异常”，字体字号不得猜测，不写“待确认”或“需要与业务核对”。

验收表列顺序固定为设备、截图、问题描述、优先级、验收状态、备注。截图列放独立的设计稿/设备对比图，设计稿标题写“设计稿”；红框仅标在设备图上且只圈本行问题。缺项时展示设计目标并圈出设备中能证明缺失的区域。每行图文对应，记录框选坐标和证据路径；不复用其他问题的红框图。

超过 2 个框的间距问题，在备注放 Figma 研发模式的正确间距截图；其他问题可放无标记的设计稿截图或留空。其余测量留 JSON。状态一律“待修复”；未经用户授权不写通过、不通过或已修复。沿用原表格式和 P0/P1 规则。

文字属性从可编辑 Figma 节点读取；图片或转曲文字不猜属性，也不从截图推断 dp/pt。

每条发现使用稳定且唯一的 ID，并记录类别、设备原图 `bbox`、设计依据、预期、实测、差值、建议和同源局部证据。沿用用户优先级：功能/模块/内容缺失，模块尺寸、布局、样式、圆角明显错误，内部元素、图片容器或 icon 尺寸不符，固定文案或文字样式不符，设备适配问题，以及超过4px且明显破坏布局的间距差记 P0；4px以内且影响较低的间距差记 P1。卡片底色缺失属于模块样式错误，不自动降为 P1。图片容器、icon 节点框和图形可见边界分别测量，缺项、尺寸、位置、裁切、遮挡分开登记。

页面汇总、`review.json` 与 Excel 的问题 ID、测量和证据必须一致。每个问题的证据需包含对应设计区域、同源设备裁片和对位截图；未验收、未覆盖项单独注明原因。按当前电子表格 Skill 使用 `@oai/artifact-tool` 创建可编辑 `.xlsx`，保留旧表手改字段，不静默覆盖。复测后记录新截图和结果；验收状态变更须由用户明确授权。

### 完成前核对

- 输入清单中的每张截图都恰好有一个最终状态：已发现问题、已验收未发现明确差异、未验收（简述原因）或未处理（附原因）；分别统计覆盖数与问题数。
- 汇总、各 `review.json` 与 Excel 的问题 ID 和数量一致；每项问题都有有效来源截图、设计依据、可读的局部标注证据及并排/红色叠图链接。
- 抽查全部证据链接可打开、截图与问题描述相符，且编号、页面组和 bbox 对应正确；核实每个截图清单都有当前对位/叠图链接。缺证据或配对依据不足的项目不报为验收完成。
- 最终回复给出页面问题汇总和配对进度链接，并直接链接问题证据；对无明确差异的页面提供并排图链接，同时说明未配对和未覆盖范围。

## 适用范围

本流程不会自动操作手机、翻页或截图；没有可用的 Figma 连接时，不会读取设计文件中的源属性；仅凭一张 720px 设计图无法确定所有不同宽度设备的响应式规则；静态截图也不能验证动画和运行性能。遇到这些情况时，用中文说明本轮能确认的范围，并将未验证事项单独记录。
