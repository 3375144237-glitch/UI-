# Figma 与 App 界面验收

当用户提供设计稿和 App 截图，并要求检查界面还原情况时，使用本 Skill。

## 开始前

1. 创建文件或新的验收目录前，完整阅读 workspace 根目录的《问题与报错日志.md》。发现可复用的问题、原因或解决方法时，记入该 workspace 中心日志，与每轮变化的钉钉链接分开保存；不自动复制到线上验收文档。
2. 按批次收集 Figma 链接或设计稿、截图文件夹、设备名称和 REM/PX 实现方式。PX 另需设备自身 @2x 目标宽度，以及截图已为 @2x 的声明或截图倍率；REM 按宽 720px 等比处理。共用信息只收集一次；页面名称、可见状态和设计稿配对由 Codex 逐张识别、记录，不要求用户逐页填写。不得按机型名称或物理分辨率猜倍率。
3. 推荐把待比较的设计稿放在 `screenshots/design/`，把人工手机截图放在 `screenshots/device/`。也可以直接使用聊天附件的本机路径；路径传给命令后，程序会将原图副本收进验收目录。两个输入目录中的图片和 `outputs/` 报告默认被 Git 忽略，不会随代码提交。
4. 保留用户提供的原图，不覆盖、不修改。每轮验收使用新目录：`outputs/design-review/<日期>/<页面-设备>/`。原图副本放在该目录的 `inputs/`，归一图、证据、`review.json` 和 Excel 放在该轮目录。同步代码仓库时只提交可复用规则/代码；该项目的报告、工作簿、截图和证据不带入代码提交，除非用户另行明确要求。
5. 某批次必需的缩放信息缺失或冲突时，暂停该批次缩放，并写明缺少的输入和受影响范围；其他信息完整的批次可继续。页面覆盖记录用“已验收、未验收、未处理”区分处理进度；问题表中的验收状态统一写“待修复”，不把覆盖进度当作验收结论。
6. 检查 Figma 页面并复用已有“<项目名>验收”页；用户另给目标时沿用。分批导入后逐模块对位、登记问题和归档证据，再检查图层与画布确认落位。原设计页不改。提示未同步时只记录本机状态，不宣称共享端可见，也不主动同步或重连。
7. 对照前读取 Figma 评论正文、回复和锚点。优先运行 `~/.codex/bin/figma-comments "<Figma链接>" --json`；带 `node-id` 时结果只覆盖该节点及子节点。把评论范围和 PX/REM 规则绑定到对应画板/模块；节点文本搜索不包含评论，不能替代评论读取。读取失败时记录未读范围，不发布受影响范围的最终结论。

同一设备截图文件夹共享用户确认的设备与缩放信息。保留原文件名、另编序号；不从文件名或分辨率猜页面及倍率。

## 多页面批量验收

- 多页面截图不必重命名或逐页说明。清点编号后结合画板、标题、文案和布局配对可见状态；不推断截图外状态。证据不足记“未验收”并说明原因。
- 在 `配对与进度.md` 逐图记录编号、原路径、页面/状态、Figma 画板或区段、配对依据、把握度和输出目录；每张图须可追溯到设计稿与原图。信息不足、状态不明或配对不唯一时标“未验收”并说明原因。
- 页面使用稳定组号（如 `P08`），问题连续编号；各截图保留独立目录，汇总页集中索引。跨设备同一差异可共用问题 ID，但每台设备仍保留截图、原图 bbox 和测量；仅按 `shared_issue_id` 合并，不凭相似文字或编号推断。
- 先验收明确配对的图片；相似页面、重复模块、多个版本或缺设计依据的项目标“未验收”。按批更新进度，并确保每张输入图均有覆盖状态；无问题页面也要记录，没有截图的状态不算已验收。
- 页面识别与配对由 Codex 执行；现有 `compare` 命令每次只处理一组配对，不会独立识别整个文件夹。`--page` 由 Codex 按证据填写；用户手动运行时也可省略该可选参数。

## 多张截图对应长设计稿

- 逐张按唯一标题、文案、图标、顺序及布局锚点配长稿区段，不能用滚动位置单独配对。
- 配对表记录原文件名、设计起点/区段、页面状态、依据和把握度；相似候选或锚点不足记“未验收”并说明缺项。
- `--design-y` 用设计稿 @2x 纵坐标，从该处裁取与归一设备图等高的连续区段；每张截图独立输出。
- 跨相邻区段可选连续范围，不得拼接不连续区域；必要时用前后截图核滚动连续性。
- 尺寸相同后才运行像素差异定位。PX 设备宽度不同于720px时不拉伸设计稿；按 Figma 约束判断，不足则注明未验收依据。

## 处理截图

设计稿画板本身宽 720px，这已是本项目 @2x 验收基准；手动导出选 1×，确认图片宽 720px，不再选 2×。也可先提供 Figma 链接，由 Codex 经可用连接读取画板并核对参考图实际尺寸；无法读取或无法取得合适参考图时，再请用户补充导出图。

- REM：运行命令时使用 `--mode rem`。程序会把设备截图副本等比缩放至宽 720px，高度随比例变化。
- PX：使用 `--mode px`，并填写用户确认的设备自身 @2x 宽度 `--target-width`。如果截图已经是该设备的 @2x 图，增加 `--already-2x`；否则填写用户确认的截图倍率 `--screenshot-scale`。程序会检查倍率推算结果是否与目标宽度吻合。
- 设备图中的深色“测试 ▶”悬浮按钮、红色“调试”圆形按钮、蓝色“LiveHybrid”标记不参与 UI 验收，不将标记本身或其遮挡造成的像素差异登记为缺陷。若遮住待验收内容，在截图文件夹中找同设备、同页面、同状态且露出该区域的补充截图；核对位置与内容后，用补充截图验收被遮挡处，并记录来源文件及原图坐标。找不到可靠补图时，只将该区域记为未验收，不推断遮挡下的界面。
- 不得拉伸设备图或修改原图。全屏红色 50% 叠图只是初始定位参考，不能当作验收结果。将设备图副本裁成单个模块/元素后，把对应裁片移到设计稿的对应模块；按相同文字、图标、边缘或中心锚点调位置，尽可能让轮廓与字形无缝重叠。裁片只移动、不缩放、不重排内部元素；无法重合后再判断尺寸、周围间距或位置差异。PX 按用户提供的换算尺寸处理；REM 先把整张设备截图等比例缩到设计稿宽度，再裁模块。所有位移和测量都记录为处理后设备截图 @2x 像素。
- 验收弹窗时先从设备截图中独立裁出弹窗，只比较弹窗与设计稿弹窗。将两张弹窗裁图的顶部边缘对齐，不使用状态栏、屏幕顶部或整屏位置作锚点；弹窗内部仍要逐模块/逐元素移动对位。
- 每项问题证据包含设计区域、带编号的同源设备原图裁片及移到设计锚点的红色 50% 对位图；在 `review.json` 记录来源、原图 bbox、设计区域和目标位置。整屏叠图或无设计参照的裁片不足以作为证据。
- 对比图出现文字重影时，回查同状态原始设备图和对应 Figma 文字节点，先排除设计/设备叠图造成的双影。聊天裁片或叠图无法追溯时记为“未验收”，说明缺少的原图/节点，不作为确认问题或覆盖数。

REM 命令示例：

```bash
.venv/bin/python scripts/ui_review.py compare --design screenshots/design/page.png --device screenshots/device/page.png --mode rem --device-name "设备名称" --page "首页/默认态" --out outputs/design-review/YYYY-MM-DD/首页-设备
```

PX 命令还需增加 `--target-width <设备自身@2x宽度>`，并根据截图情况选择 `--already-2x` 或 `--screenshot-scale <用户确认的截图倍率>`。

程序会保留输入原图，并生成处理后的图片、三种锚点叠图、`review.json`、差异预览图和 `report.xlsx`。`align` 可调整当前叠图并更新复核记录：

```bash
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment left --offset-y 0
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment right --offset-y 12
.venv/bin/python scripts/ui_review.py align --session <验收目录> --alignment center --offset-y 0
```

纵向偏移用归一后设备图 @2x 像素，正数下移。整屏锚点只用于初定位；最终必须在 Figma 里逐模块、逐元素对位，弹窗只按弹窗顶部锚点。

## 验收执行顺序

严格按以下顺序完成；缩放资料不全时暂停该截图，Figma 配对、状态或版本依据不足时记录为未验收，并简述缺失依据。

1. **检查缩放**：记录原图尺寸、用户确认的方式/目标宽度/倍率，以及处理后尺寸与比例；按前述 REM/PX 规则换算，不按机型猜倍率或拉伸图片。
2. **在 Figma 比对**：确认目标画板、状态和版本，复用已有验收页；先读节点边界、自动布局与约束，列出验收范围内设计稿上每个应显示的元素（重复组件逐实例列出），再逐个到同倍率设备截图中查找并对位。每项比对样式、位置、大小；弹窗量四边及内部间距。对可编辑文字用 `getStyledTextSegments(['fontName','fontSize','lineHeight','letterSpacing'])` 读取属性并将值、节点 ID 记入 JSON；只报设备表现支持的差异，不猜。状态、版本或响应式依据不足时标未验收，宽度不同则按约束推导预期。
3. **截图并记录**：Figma 验收页留设计、设备及对位图，不写问题描述。以当轮钉钉链接为主表，缺链接先询问；沿用六列原格式，每行一张比对图。输入或插图前后核对目标坐标、单元格与画布；地址文本误入单元格时暂停并修正。人工改过的数据不覆盖，版式调整不触发保护。完成后刷新回读并确认保存；测量、原图 bbox、证据和 ID 记入 `review.json`，本地表仅归档。

## 人工检查与记录

### 检查顺序与卡片间距

每页依次检查功能/状态、模块外观、内容、图片/icon、文字、适配和间距。重复卡片按实例检查；独立差异分别编号，不合并位置、尺寸和间距问题。

以设计稿元素清单为覆盖基准，在 `review.json` 逐项记录 Figma 节点 ID、设计 bbox、对应设备截图原图 bbox、样式/位置/大小的实测与结论。应显示却在截图中找不到的元素，核实状态和可见范围后登记缺项；被遮挡、位于截图视口外或缺少足够设计约束的元素标“未验收”并写原因，不能标通过。隐藏/辅助图层及评论明确排除的区域不列入应显示清单。完成前核对清单与逐元素结果一一对应，不能以模块整体正常代替。

### 文案性质与视觉验收

开始文字验收前完整阅读 [`COPY-CLASSIFICATION.md`](COPY-CLASSIFICATION.md)，并按其中的四类判定优先级逐节点记录类别、依据和把握度。`COPY=FIXED / DYNAMIC / TEMPLATE` 对应 F/D/T；低把握度及无法消解的依据冲突归 U。Figma 评论要锚定节点，容器标记作用于子树。四类均检查文字样式；图片中的文字不作文字分类。

逐节点检查完成后提供本轮文案性质待确认表；U 项不登记为问题、不计入问题数、不得标通过。用户确认后更新项目根目录 `copy-registry.json` 并补查新确认的 F 文案。完成前核对每个可编辑文字节点均已分类，且只有 F/T 固定部分产生文案内容问题。

卡片父容器的位置与内部间距分开检查，不能只量子元素或只看整屏。记录父容器相对画板的 bbox/顶边，再逐个识别子元素并记录原始截图 bbox；分别计算父容器位置、元素距卡片四边的间距和同排/列元素间距。以 Figma 节点/自动布局为设计值，同倍率设备截图为实测，记录差值（设备减设计，@2x px）。超出容器记负值和方向。

先记录原始位置和间距，再做视觉对位。移动设备裁片只用于叠图的副本；不得用移动后的坐标计算原始间距，也不得移动卡片父容器来掩盖子元素差异。设计和设备宽度不同，按 Figma 约束换算预期，不缩放截图来消除差异。

在 `review.json` 为每张卡、每个子元素记录 `spacing_checks`：容器/元素名称、Figma 节点或来源、设计 bbox、设备 bbox、设计与实测四边间距、差值、状态（通过/问题/未验收）及测量把握度。每个可见卡片及子元素都要有记录；没量完或无法配对时页面只能是部分验收。只有像素图而无法确定元素布局框时，记录可见边界并标“估算”；不得把估算写成精确布局值。Figma 版本依据不足时，依赖该版本的测量记录为未验收并说明原因；状态专属或无法配对的元素不作推断，共享元素仍按设计稿状态测距。

统计证据图中设备侧红框数（不计设计稿侧）。1-2框写明对象、属性和正确设计值；纯文案写“XX区域文案内容与设计稿不一致”，不复述文本；缺项指出应有项。超过2框简要归纳，多处写“不对，需要与设计稿保持一致”，细值留JSON。值须来自 Figma 属性或研发模式；不猜字体字号，不写“样式不对”“显示异常”“待确认”或“需要核对业务”。

验收表列顺序固定为设备、截图、问题描述、优先级、验收状态、备注。截图列放独立的设计稿/设备对比图，设计稿标题写“设计稿”；红框仅标在设备图上且只圈本行问题。缺项时展示设计目标并圈出设备中能证明缺失的区域。每行图文对应，记录框选坐标和证据路径；不复用其他问题的红框图。

超过 2 个框的间距问题，在备注放 Figma 研发模式的正确间距截图；其他问题可放无标记的设计稿截图或留空。其余测量留 JSON。状态一律“待修复”；未经用户授权不写通过、不通过或已修复。沿用原表格式和 P0/P1 规则。

导出前按以上规则核对六列表头、状态、框数话术及逐行截图/红框/描述/证据。发现格式误差先修本地副本；钉钉编辑遵守人工修改保护规则，不用旧 Excel 覆盖。

需要给证据图加标题时，使用 `scripts/label_evidence_header.py` 在原图上方新增标题条；需要把研发模式截图和备注写入验收表时，使用 `scripts/add_review_note.py` 输出新工作簿副本。参数示例见项目 README。

文字属性从可编辑 Figma 节点读取；图片或转曲文字不猜属性，也不从截图推断 dp/pt。

每条发现使用稳定且唯一的 ID，并记录类别、设备原图 `bbox`、设计依据、预期、实测、差值、建议和同源局部证据。沿用用户优先级：功能/模块/内容缺失，模块尺寸、布局、样式、圆角明显错误，内部元素、图片容器或 icon 尺寸不符，固定文案或文字样式不符，设备适配问题，以及超过4px且明显破坏布局的间距差记 P0；4px以内且影响较低的间距差记 P1。卡片底色缺失属于模块样式错误，不自动降为 P1。图片容器、icon 节点框和图形可见边界分别测量，缺项、尺寸、位置、裁切、遮挡分开登记。

页面汇总与 Excel 按唯一问题计数，`review.json` 和详情保留各设备实例、测量与证据。每项证据包含设计区域、同源设备裁片和对位图；未验收、未覆盖项注明原因。按当前电子表格 Skill 使用 `@oai/artifact-tool` 创建可编辑 `.xlsx`，保留旧表手改字段，不静默覆盖。复测后记录新截图和结果；验收状态变更须用户明确授权。

### 完成前核对

- 每张输入图只取一个最终覆盖状态并统计；唯一问题数按共享 ID 计，各 `review.json` 保留设备实例。每项须有来源、设计依据、原图 bbox 和对位证据；遮挡或配对不足处不计为已验收。
- 验收表核对六列名称、待修复状态、文案/框数话术及逐行截图。抽查证据可打开且与问题、ID、页面组和 bbox 对应；缺证据或依据不足的项目不报完成。
- 汇总页链接覆盖进度和问题证据；无明确差异的页面链接并排图，并说明未配对、未覆盖范围。

## 适用范围

本流程不会自动操作手机、翻页或截图；没有可用的 Figma 连接时，不会读取设计文件中的源属性；仅凭一张 720px 设计图无法确定所有不同宽度设备的响应式规则；静态截图也不能验证动画和运行性能。遇到这些情况时，用中文说明本轮能确认的范围，并将未验证事项单独记录。
