# 文案性质分类规范

## 分类与适用范围

每个可编辑文字节点必须分类：

| 类别 | 含义 | 内容比较 |
| --- | --- | --- |
| F 固定 | 写在 APP 中 | 逐字比较 |
| D 动态 | 后台、运营或用户数据下发 | 不比较具体值 |
| T 模板 | 固定文本与变量混合 | 固定部分逐字比较，变量按 D 检查 |
| U 待确认 | 依据不足或冲突 | 暂缓内容比较，等待用户确认 |

分类只决定内容比较方式；四类都检查字体、字号、字重、颜色、行高、字距、对齐、文本框位置和相邻间距。图片里的文字（如封面书名、Banner 字）不做文字分类，按图片检查尺寸、裁切、位置和遮挡。

## 判定优先级

高优先级来源覆盖低优先级来源：

1. 用户已确认的项目文案登记表。
2. Figma 评论 `COPY=FIXED / DYNAMIC / TEMPLATE`。验收前用 `~/.codex/bin/figma-comments "<Figma链接>" --json` 读取评论正文、回复和锚点；容器评论对整个子树生效。
3. 图层名开头的 `【固定】` 或 `【动态】` 标记；容器标记对整个子树生效。此标记可选，不要求设计师必须添加。
4. 组件实例文字被覆盖，且主组件将其定义为可替换的 `TEXT` 属性：判 D，把握度中。
5. 结构规则。
6. 类型清单。
7. 以上均未命中时判 F。

命中依据矛盾且无法按优先级消解，或只有弱信号时判 U。每节点记录类别、依据（规则编号/标记来源）和把握度（高/中/低）；低把握度一律归 U。

## 类型清单

以下类型规则是内容默认值；依照优先级可被用户确认、评论、图层标记或强结构证据覆盖。

**D 动态**：书名、专辑名、课程名、系列名；作者、讲师、出版社；简介、摘要、描述；目录、章节、课时名；题干、选项、解析、文章正文；运营标签/分类；昵称、用户名、ID、学号、年级、班级、学校；等级、积分、金币、星星、会员状态/到期日、学习记录、最近学习；价格、原价、折扣、人数、阅读/播放/点赞量、进度、完成数、得分、正确率、排名、时长、剩余时间、倒计时、文件大小；日期、时刻、星期、相对时间；Banner/活动标题和副标题、公告、通知、推荐语、运营弹窗、搜索热词/推荐词；消息、评论、通知正文、搜索/筛选结果；版本号、缓存大小、设备名；设计占位文案，如「书名书名书名」「XXXX」「0000」「示例文字」「Lorem」。

**F 固定**：导航栏标题和返回文字；功能按钮；模块/分区标题；表单标签和固定输入提示；空状态、错误、加载、引导和权限说明；单位、量词、固定前后缀、固定标点；协议、隐私、版权文字；系统弹窗标题和按钮。

**默认 U，首轮请用户确认**：底部 Tab 名、频道名、首页金刚区入口名、活动入口按钮和角标（如「NEW」「限免」）、可配置列表中的「全部」「更多」。用户确认后写入登记表。

**T 模板**：固定字与变量混合即判 T，例如 `共{n}课`、`已学{a}/{b}`、`¥{price}`、`第{no}讲-{name}`、`剩余{n}天`、`{n}人在学`。变量值不比较；变量格式按固定规则检查，包括小数位、千分位、货币符号、日期格式（`2026-10-29` 与 `10月29日` 不可互换）和百分号。

## 结构证据与禁用依据

**强 D 信号**：同一组件或结构在列表、网格、轮播中出现至少两次，同一位置的文字各不相同，只将该位置判 D；使用占位文案的设计稿也判 D。

**强 F 信号**：重复组件同一位置的文字完全相同（例如卡片上的「去学习」）；单例文字位于导航栏、Tab 栏、按钮、分区标题、表单标签；同一句文字在多个页面或状态完全相同。

上列默认 U 的项目专属文案是通用强 F 结构规则的例外；没有用户确认或更高优先级标记时仍为 U。

设备截图与设计稿文字不同不能单独作为 D 依据，否则会放过写错的固定文案。差异只能作为辅助证据，且类型清单也支持 D 时才可采用。不能根据字体、字号、颜色或文字长短判分类。

## 各类检查与问题登记

- **F**：完整检查样式，并逐字比较内容，包括标点、空格、全/半角、大小写和数字。
- **D**：完整检查样式；内容不得为空或露出占位文案。检查换行、最大行数、超长截断及省略号位置、溢出和遮挡。按 Figma 固定宽度/自适应/行数约束评估长短不同的文案；缺约束时，极端长度表现记未验收。
- **T**：完整检查样式；固定部分逐字比较，变量值不比，变量格式按类型清单检查。
- **U**：完整检查样式；内容比较暂缓。不得登记为问题或计入问题数，也不得记为通过，待用户确认后补查。

在批次清单或 `review.json` 的 `copy_checks` 中逐节点记录 node ID、节点名、类别、依据、把握度及需要的内容证据；不能只记录有差异的文字。

只有 F 类和 T 类固定部分可登记内容问题，话术为「XX区域文案内容与设计稿不一致」，不复述原文。D 类的换行、截断、溢出、样式问题仍照常登记。U 项放入文案性质待确认表。

## 待确认表与项目登记

每轮输出一份待确认表，每个 U 节点一行，列为：页面、节点名称和 ID、设计稿文案、设备文案、建议分类、依据。用户可批量回复「动态」「固定」或「模板（附格式）」。

用户确认后，将已确认的 F/D/T 结果写入项目根目录 `copy-registry.json`，结构如下；可选字段无值时省略，未确认的 U 不写入：

```json
{
  "records": [
    {
      "figma_file_key": "file-key",
      "node_id": "123:456",
      "page_name": "首页",
      "design_text": "我的图书",
      "classification": "F",
      "confirmed_at": "2026-10-30"
    }
  ]
}
```

下一轮先按「文件 key + 节点 ID」查表，命中后沿用。未命中再用「页面名 + 设计稿文案」匹配；此类匹配只作参考，把握度最高为中。设计稿文字已变化则旧记录作废、重新判断；节点删除后保留记录但不再使用。用户确认新的 F 节点后补做逐字比较并登记发现的问题。

## 完成前核对

- 每个可编辑文字节点都有类别、依据和把握度；图片内文字不混入清单。
- 所有 U 节点均出现在待确认表中；没有被登记为问题或标为通过。
- 文案内容问题只来自 F 或 T 的固定部分；新确认的 F 已补查并更新登记表。
